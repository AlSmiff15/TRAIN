# TRAIN — no login edition

This version launches directly to the dashboard. No account, Supabase or cloud connection is required. Training records and dashboard customisations save on this device. Exercise demonstrations remain included.

## Update GitHub Pages
Upload the contents of this folder to the root of your existing GitHub Pages repository, replacing older files, then refresh TRAIN in Safari. If the Home Screen version still displays the old login, close and reopen it after Safari has loaded the updated website.

## Protect existing workouts
**Before replacing files**, use the old app’s Settings > Download encrypted backup or Export backup. Do not delete the Home Screen app or clear website data. This release uses the original `train_tracker_v1` local storage key, so existing data saved under that key on the same origin should remain accessible. Data saved only under a Supabase user-specific key (`train_cloud_user_...`) is not automatically migrated. If you used the account version to save workouts, export them from that version and import the backup into this one. Keep a copy of the original ZIP until migration is confirmed.

There is no automatic cross-device sync or recovery after device loss. Export encrypted backups regularly.


## Saved block recall fix
The active block's **View all weeks** button now opens its saved weekly schedule directly.
The earlier button pointed to an element that only existed in the Saved blocks archive,
so it appeared to forget the programme. Auto-created programmes now save their active
block identifier too. Existing saved blocks are not cleared or regenerated by this update.
Back up your TRAIN data before replacing website files; retain the same GitHub Pages URL
and do not clear Safari/Home Screen app storage. If a block was never actually saved,
the app cannot reconstruct its exact original sessions.

## Replacing an active programme
Training Blocks → Create or replace your block → Save & activate new block. The previous active programme is moved to Saved blocks with status finished. Workouts and unfinished sessions are retained. You can reactivate an archived block later. The replacement action no longer requires a separate confirmation dialogue, which could prevent saving on some devices. Export an encrypted backup before updating.


## Create button repair
The Create button now gives visible progress, success, and actionable errors. It keeps the previous active block if saving fails. It also defaults replacement programmes to today rather than the end of the previous block. Verify on your iPhone after publishing; browser testing has not been completed.


## Diagnostic update
This release forces a new JavaScript URL to bypass old cached files and reports JavaScript startup errors beside the block save button. It does not erase saved training data.
If Save & activate remains unresponsive, open Training Blocks and report any red or visible error text. If no error appears, verify that the deployed website is serving the updated `index.html` and `train-core.js` from the same directory. Do not clear Safari storage or uninstall the Home Screen app.


## Critical block saving repair (v10)
The morning readiness functions were accidentally placed outside TRAIN's main app
scope, while the programme renderer tried to call `morningFor` before it was
initialised. This caused `Cannot access 'morningFor' before initialization`
and prevented block creation. All readiness functions now share the app scope,
and `morningFor` is declared as a hoisted function.
The update preserves the existing `train_tracker_v1` storage key and does not
delete or migrate saved data. Back up your data before updating. Upload all files
to the same GitHub Pages location and reopen Safari to load the new cache.


## Workout timer update
Live strength sessions now display an HH:MM:SS active-workout timer.
Save & leave pauses time; reopening resumes. Finished workouts use active
elapsed time instead of rounding the wall-clock start/end difference.
A per-exercise rest countdown starts when a set is checked complete, with
Restart and Skip controls. Countdown deadlines use absolute timestamps so
they keep accurate time when iOS suspends the app. iOS may suppress vibration
while TRAIN is in the background; return to TRAIN to view the countdown.
Run sessions still support manually entered duration. Existing workout history
is unchanged. This does not retroactively repair incorrect historic durations.
